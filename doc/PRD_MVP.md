# drive_story MVP 要件(2026-08-28)

元案(ユーザー提示の Drive Story Generator 要件)に、競合調査(`COMPETITORS.md`)を当てて磨いたもの。
**元案から変えた点は §0 に集約**。変えていない部分は元案どおり採用。

前提: **大学のプロジェクト。全機能を無料で提供し、課金・サブスクリプション・広告は実装しない。**

## 0. 元案から変えた 5 点(と理由)

| # | 元案 | 変更 | 理由 |
|---|---|---|---|
| 1 | 目的 = 拡散ループ(Drive→Story→共有→保存→再走) | **MVP の目的は「共有までの摩擦をゼロにする」1 点。ループは第2弾** | ユーザー 1 人目にループは存在しない(他人の Drive が 0 件)。ループを先に作ると、価値 0 の機能に MVP のコストを割く |
| 2 | Must に「Save Drive」「Drive this route」 | **MVP から外す。共有 URL は"見るだけの静的ページ"に縮小** | 保存にはアカウント+サーバ+認証が要り MVP コストが数倍。画像自体に地名・ルート形・距離が入っていれば「行きたい」は画像だけで作れる |
| 3 | 体験の入口 = ドライブを 1 回記録すること | **初回起動で「カメラロールの過去の写真から Story を作る」入口を追加(TTFV 短縮)** | Relive も Strava も「1 回活動しないと何も出ない」。ここが最大の離脱点。過去写真の EXIF(時刻+GPS)だけで Story は作れる ⇒ **インストール直後に価値を体験させられる**。競合が誰もやっていない |
| 4 | ルートマップ = ブランド化した簡易マップ | **必然として確定。地図タイルを一切使わない自前ポリライン描画** | 元案の判断は正しいが理由がもう 1 つある: 地図タイルを画像に焼いて SNS 配布すると帰属表示・再配布の規約に触れる。自前描画なら規約リスクが消え、同時にプライバシー(生活道路・店名が写らない)も解決する |
| 5 | テンプレ 4 種はすべて写真前提 | **Night / Editorial は「写真 0 枚でも成立する」構成を必須要件に** | 写真が下手・少ない日でも Story が破綻しない保険。生成失敗率がそのまま Story Generation Rate に効く |

## 1. 一言

ドライブを、そのまま貼れる 1 枚に変える。**記録アプリではない。変換アプリ。**

最重要画面は **「走行終了 → Story プレビュー」**。ホーム画面より先にこれを完成させる(元案 §27 に同意)。

## 2. MVP スコープ

### Must
- GPS 記録(前景 + Live Activity。**Always Location は使わない** — 審査とバッテリーの割に合わない)
- 距離・所要時間の算出
- 走行時刻レンジ + 位置での写真自動抽出(Photos / PHAsset の creationDate・location)
- 写真のルート上への自動配置
- 地名の自動特定(逆ジオコーディング)+ タイトル自動生成
- **Story 自動生成(9:16 / 1080×1920)・テンプレ 4 種**
- 編集はトグルのみ(テンプレ切替 / 写真差し替え / タイトル編集 / 表示項目 ON-OFF)
- 出発・到着地点の自動マスク(既定 500m)
- 共有シート経由の Instagram / TikTok / X 共有 + 画像保存
- **過去写真モード**(ドライブ未記録でも Story を作れる入口)
- 共有 URL(静的な閲覧ページのみ)

### Must not(MVP で作らない)
自前ナビ / CarPlay / フィード・投稿 / フォロー / DM / クラブ / グループドライブ / 動画生成 / Save Drive / Drive this route / 天気予報 / AI 旅行プランナー

第2弾で戻す: Save Drive → Drive this route(Apple/Google Maps 連携) → 投稿フィード。

## 3. 開発順(この順で作る)

1. **Story レンダラ**(ダミーデータ → 1080×1920 PNG 書き出し。テンプレ 4 種)
2. **自前ルート描画**(ポリライン簡略化 + 正規化 + START/GOAL/写真ピン)
3. **写真マッピング**(Photos 権限 → 時刻・位置照合 → ルート位置算出)
4. **GPS 記録**(開始/終了 + Live Activity + 中断復帰)
5. 逆ジオコーディング + タイトル生成
6. 編集 UI(トグルのみ)
7. 共有 + 保存
8. 過去写真モード
9. 共有 URL(静的ページ)

1〜3 はドライブを 1 回もせずに実装・検証できる。**先に絵ができるので、価値の検証が最速で回る。**

## 4. データモデル

元案 §18〜20 をそのまま採用。追加/明確化のみ:

- `Drive.routePoints[]` は記録用(lat/lon/timestamp/speed)。**Story 用は別途 Douglas-Peucker で簡略化した Polyline を保持**(元案 §20 と同じ判断)
- `DrivePhoto.routePosition` は 0.0〜1.0 の正規化位置(描画側が座標を持たないで済む)
- `Drive.maskedRadius`(既定 500m)を Drive ごとに保存 — 生成時ではなく記録時に決める(あとから公開範囲を変えても一貫する)
- MVP はローカル完結。共有 URL のためだけに最小の公開ペイロードを送る
- **永続化は SwiftData ではなく Codable + JSON を採る**(2026-08-28 決定) — `routePoints` が `CLLocationCoordinate2D` を含み `@Model` に素直に載らず、結局 Codable と同じ手間にマイグレーション責務が乗るだけのため。`../car_ui` に動作実績のある atomic write をそのまま使う。差し替え余地は `protocol` で残す

## 5. テンプレ 4 種(`vision/` に決定稿の見た目あり)

| ID | 見本 | 主役 | 写真 0 枚 |
|---|---|---|---|
| `scenic` | `vision/hakone-morning.png` | 実写 1 枚 + 下部ルートパネル | 不可(写真必須) |
| `route` | `vision/chirihama-coastal.png` | ダークマップ + 写真ピン | 不可(ピン写真必須) |
| `editorial` | `vision/venus-line.png` | 雑誌組版。写真 + 淡色マップ | 可(タイポ主役に切替) |
| `night` | `vision/tokyo-night-loop.png` | 黒×赤。ネオンのルート軌跡 | **可(ルートの形だけで成立)** |

共通要素: ロゴ / タイトル / 距離 / 所要時間 / タグ / ルート図 / CTA。
差は配色とルート図の見せ方だけ ⇒ **1 つのレンダラ + テーマ定義**で実装する(テンプレごとに画面を作らない)。

## 6. 命名

- 英語ストア名は "Drive Stories"(米国既存アプリ)と衝突するため回避する。
- 内部コード名 `drive_story` は維持。表示名は `/store-prep` 時に ASO 込みで決定。
- 制約(`biz/VALUE_PLAYBOOK.md` + 命名メモ): 造語・幼い響きは使わない。実在語ベースで機能が伝わる中立な名前。

## 7. リスク

| リスク | 対処 |
|---|---|
| バックグラウンド位置情報の審査 | Always を使わない。When In Use + Live Activity。Purpose String に「走行中のルート記録のため」と具体を書く |
| 地図タイルの SNS 再配布 | 自前描画で回避(§0-4) |
| 写真が少ない日に Story が破綻 | `night` / `editorial` を写真 0 枚対応に(§0-5) |
| 自宅特定 | 既定 500m マスク。設定で 500m/1km/2km |
| 記録アプリと誤認され、変換の価値が伝わらない | ストア 1 枚目を「完成した Story」にする。記録機能を主要訴求にしない |

## 8. KPI(元案 §26 を採用・優先順)

1. **Story Generation Rate** = Story 生成数 ÷ ドライブ記録数(過去写真モード含む)
2. **Share Rate** = 外部共有数 ÷ Story 生成数
3. TTFV = インストール〜初回 Story 生成の中央値(**過去写真モードの効果指標**)
4. 再生成率 = 同じドライブを別テンプレで作り直した回数 ÷ Story 生成数

第2弾で Drive Conversion / Re-drive Rate を追加。
